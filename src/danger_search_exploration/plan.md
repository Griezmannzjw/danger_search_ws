# AGENTS.md

## 1. 项目与文档职责

本仓库是基于 `ROS1 Noetic + Gazebo Classic + Unitree A1` 的未知多楼层室内探索赛题。机器人需要自主探索随机楼栋、识别危险源，并输出危险源的 `world` 坐标。成绩同时考虑探索时间、危险源召回率和虚警率。

本文档适用于整个仓库，是探索与任务规划的当前共识、接口基线和开发约束。修改代码前必须先阅读：

- `README.md`
- `docs/algorithm-interfaces.md`
- `docs/competition-rules.md`
- `docs/doors-and-elevator.md`
- `docs/evaluation.md`
- `docs/sensors-and-topics.md`

### 1.1 更新规则

发生以下情况时必须同步更新本文档：

- 用户提出新的目标、疑虑、优先级、算法选择或约束。
- 定位、建图、导航、感知、门、电梯、任务或结果接口发生变化。
- 仿真证明现有算法、参数、结束条件或恢复策略需要调整。
- 赛题规则、允许接口、禁止数据、评分方式或启动流程发生变化。
- 新增关键模块、状态、测试标准、风险或已知限制。
- 已确认实现应取代本文档中的旧基线。

更新要求：

- 使用 `YYYY-MM-DD` 记录日期；当前日期为 `2026-07-23`。
- 优先修改对应章节，不在文末重复追加同类信息。
- 算法变化需说明原因、替代对象和验证方法；仍有价值的旧结论移入决策记录，不静默删除。
- 参数必须标明是初始值、实验值还是确认基线；单场景结果不得泛化。
- 实验更新需记录随机场景数量、关键指标和比较对象；原始数据放独立实验文档。
- 用户要求与正式规则冲突时以正式规则为准，并明确记录冲突。
- 更新后检查 Markdown、文档一致性和改动范围。

## 2. 目标、边界与优先级

### 2.1 当前目标

当前负责人专注于未知环境探索与任务规划：持续选择高价值、可到达的目标，尽快完成所有可达楼层和房间的有效探索，提高危险源被感知模块发现的概率，并及时输出结果。

任务没有硬性截止时间，但时间参与评分，因此应在保证召回率、虚警率和安全性的前提下尽快结束。返航不是结果有效或任务完成的前置条件。

当前算法主线：

> 多楼层分层任务规划 + 走廊拓扑探索 + 房间可见性覆盖 + 持久化岔路债务 + 垂直通道效用选择 + 漂移感知状态机恢复与结束。

最终比赛基线不采用端到端强化学习、纯随机游走或单纯最近前沿，优先使用确定性、可解释、可复现的传统方法。S0 为验证接口与评分链路，允许暂用 DFS 或最近可达前沿，但该策略不得被标记为最终算法基线。

评分优化优先级不是单纯“越快越好”，而是：先避免召回率跌入 `<=60%` 的零分区，再将提交虚警率控制在 `<=10%`，最后在不损害前两项的前提下争取 `exploration_time<=600 s`。由于正式算法不知道危险源真值数量，不能在线计算真实召回率，也不得用已发现数量判断完成；只能以房间可见域、拓扑债务、检测确认状态和时间计分台阶作为代理指标。

实现优先级按可验收阶段推进：

1. `S0`：用 DFS 或简单前沿跑通位姿、当前层地图、导航、基础检测、任务起止、`map -> world` 和官方结果评分链路。
2. `S1`：加入定位/地图版本、导航恢复、目标冷却、黑名单和自动结束，形成可靠单楼层简单探索。
3. `S2`：加入房间/走廊结构、遮挡视点、可见域覆盖、观察完成和检测复核，优化召回与虚警。
4. `S3`：加入分层地图、增量垂直通道假设、门电梯状态、换层恢复和多楼层调度。
5. `S4`：加入通行风险、在线代价、诊断回放、多随机场景效率指标和可选策略插件。

每个阶段必须独立通过验收；S2～S4 接口尚未提供时不得阻塞 S0/S1 启动。早期“得到分数”只证明端到端链路成立，不代表召回率、虚警率或比赛性能达标。

### 2.1.1 S0～S4 具体算法定义

后续实现、评审和 README 必须以本节为阶段算法事实源。每一阶段继承前一阶段已经验证的能力；“接口已预留”“存在类名/消息字段”或“单个 mock 能运行”不等于该阶段算法已经完成。若实验需要更换算法，必须先更新本节，记录替换原因和验证方法。

#### S0：最近可达简单前沿闭环

S0 使用确定性的 **最近可达简单前沿**，不使用随机游走：

1. 从当前层 `OccupancyGrid` 读取 `UNKNOWN=-1`、`FREE=0`、`OCCUPIED=100`。
2. 将与未知栅格四邻接的自由栅格标记为前沿，使用八邻域连通聚类，并按参数化最小长度过滤噪声簇。
3. 每个前沿簇选择靠近簇质心的自由栅格作为目标候选；候选必须位于地图内且仍为已知自由。
4. 按机器人到候选的欧氏距离由近到远排序，逐个调用 `/move_base/make_plan`；首个返回非空路径的候选作为 `MoveBaseGoal`。
5. 目标成功后基于最新地图重新提取前沿；失败、取消或超时采用有限重试，并避免立即重发完全相同的目标。
6. S0 不做自动收敛判断；无候选时保持明确等待/诊断状态，由人工调用 `/danger_search/finish` 结束。

S0 的算法目的仅是用地图驱动的非零移动跑通定位、地图、导航、检测、任务起止、`map -> world`、结果落盘和 evaluator 链路。固定旋转观察可作为到点后的可选动作，但不得把预设坐标、随机采样、危险源真值或完整布局作为正式目标来源。

#### S1：WFD 单楼层可靠前沿探索

S1 用 **Wavefront Frontier Detection（WFD）+ 聚类评分 + 有限恢复状态机** 替换 S0 的全图简单扫描：

1. 从机器人所在的可达自由区执行 BFS/WFD，只发现与当前可达自由空间相连的前沿，避免枚举隔墙或孤立自由区附近的假候选。
2. 八邻域聚类前沿，过滤小孔洞和短噪声；候选选择安全自由观察点，而不是未知栅格或障碍边缘本身。
3. 对候选计算参数化评分：

   ```text
   frontier_score =
       information_gain_weight * normalized_frontier_gain
     - path_cost_weight * normalized_make_plan_path_length
     - revisit_weight * normalized_visit_heat
     - failure_weight * normalized_failure_count
   ```

4. 先用 `make_plan` 过滤不可达目标，再选择最高分候选；使用目标迟滞避免地图轻微变化导致频繁切换。
5. 维护目标 ID、生成时地图版本、访问热度、失败次数、冷却和黑名单。导航失败按“取消目标—有限代价地图恢复—重新查询路径—冷却/换目标”执行，不无限重试。
6. 定位变为 `DEGRADED` 时收紧目标与安全裕量；`RELOCALIZING/LOST`、坐标修正版本变化或地图版本使目标失效时，暂停/取消并在稳定后重验证。
7. 连续多个规划周期无可达前沿且地图增长低于阈值时进入收敛候选；经过参数化稳定窗口后自动请求 finish。

S1 的范围仍是单楼层二维地图探索，不宣称房间视觉覆盖、多楼层完整性或低虚警复核已经解决。

#### S2：观察驱动的走廊拓扑与房间可见性覆盖

S2 在 S1 WFD 上加入 **轻量结构分区 + 持久任务债务 + 贪心可见域集合覆盖**。房间和走廊共享候选、安全过滤与任务状态机，但采用不同收益和完成条件：

1. 根据结构边界、自由空间宽度、连通关系和开口提取 `ROOM/CORRIDOR/UNKNOWN_REGION`，同时识别房门、岔路、死端和疑似垂直入口；证据不足时保留未知标签，不强行分类。
2. 每个未服务房门、岔路、走廊延伸或入口建立持久 `TOPOLOGY_DEBT`。前沿暂时消失、发生回环或机器人离开局部区域时债务不丢失；完成、有限重试后确认不可达或地图修正失效时才结案。
3. 走廊使用 WFD/拓扑候选，以地图增益、预计新开口、债务年龄和房间入口价值为正收益，以路径、风险、重复和失败为代价；死端或低收益后在拓扑图上用 Dijkstra/A* 或最佳优先搜索回溯债务，不使用纯栈 DFS。
4. 房间根据边界、内部遮挡轮廓/高度、相机 FOV 和可靠距离，从门内侧、自由空间骨架、角区及遮挡物不同侧生成观察位姿。
5. 对观察候选做二维/2.5D 射线投射，估计目标支持区域的新增可见域和遮挡后方揭示量；用“新增可见域收益减路径、旋转、风险和冗余代价”的贪心集合覆盖选取视点，再以最近邻加局部改进排序。
6. 到点后按有效 FOV 带重叠地分段旋转，并等待关联任务 ID 的 `observation_done`；空检测消息不能代表观察完成。
7. 低置信、类别不稳定、位置不稳定或疑似重复检测建立 `VERIFICATION_DEBT`，从显著不同方向生成复核视点；感知/结果模块负责最终确认、合并和拒绝。
8. 房间仅在目标支持区域达到覆盖阈值、观察事件完成且剩余死角已标记明确不可达时完成；走廊仅在相关拓扑债务完成或明确不可达时完成。

结构派生层缺失时，S2 可降级为门内侧、中心/骨架及障碍不同侧的保守多视点，但必须标记覆盖置信度降低，不能宣称达到完整 S2 基线。

#### S3：分层拓扑与垂直通道效用调度

S3 在 S2 上加入 **分楼层地图 + 增量垂直通道假设融合 + 分层任务图搜索**：

1. 每层独立保存地图、结构、访问热度、前沿、房间状态和三类债务，禁止把不同高度投影进同一探索层。
2. 对 `/mapping/vertical_connection_observations` 按稳定观测 ID 和修订号融合；状态使用 `TENTATIVE -> PARTIAL -> CONFIRMED`，错误假设用 `INVALIDATED` 撤销。未知远端楼层或出口不得猜测。
3. 疑似/部分通道先生成继续观察和入口确认债务；实际通过、双端观测或充分几何证据后才建立确认的跨层拓扑边。
4. 对同层前沿/房间动作及楼梯、电梯换层动作统一计算效用：

   ```text
   vertical_utility =
       destination_floor_unresolved_gain
     + unresolved_debt_priority
     - entrance_path_cost
     - operation_and_wait_cost
     - traversal_risk
     - localization_instability_cost
     - learned_failure_cost
   ```

5. 不固定优先楼梯或电梯；依据入口路径、等待/操作时间、目标楼层收益、风险、失败概率和定位稳定性在线选择，并用真实执行结果更新经验代价。
6. 门、电梯采用显式状态机和幂等服务：到入口、操作/等待、验证通路、进入、换层、退出、定位恢复；每一步都有超时、有限重试和失败原因。楼梯按已观测安全带/中心线分段执行。
7. 换层期间暂停普通规划；只有 `current_floor`、TF、地图和定位重新一致且稳定后，才恢复对应楼层债务并重验证目标。
8. 全局调度在分层拓扑图上选择同层债务或跨层边；仅当所有已发现可服务楼层的拓扑、房间和复核债务完成或明确不可达时才允许结束。

#### S4：风险感知效用优化、动态运动模式与可选策略插件

S4 不更换 S2/S3 的候选与安全状态机，而是在其上加入 **统一风险效用、在线经验更新、诊断回放和受约束策略插件**：

1. 将地图/拓扑增益、房间新增可见域、复核收益、债务优先级、楼层收益、实际路径与转向、通行风险、定位风险、重复、失败以及时间计分台阶统一归一化后评分。
2. 对导航、观察、门梯和换层记录实际耗时、路径长度、等待、失败、定位退化和新增收益，以指数移动平均或等价在线估计更新经验代价；不得从裁判真值构造在线奖励。
3. 根据任务语义输出 `FAST_TRANSIT`、`NORMAL_EXPLORATION`、`CAUTIOUS_OBSERVATION`、`STAIR_TRAVERSAL`、`STOP_AND_SCAN` 或等价速度上限提示。navigation 结合曲率和局部障碍生成速度，control 仍是 `/cmd_vel` 唯一发布者；探索不得直接发布速度。
4. 在 `600 s` 及其后每个 `60 s` 扣分台阶附近，用动作的边际召回/降虚警收益决定是否继续；高价值房间、唯一分支和必要复核可跨越台阶，低增益重复扫描和无边界恢复必须终止。
5. 发布 RViz 前沿、候选、目标、债务、通道和黑名单标记，并记录结构化决策日志/rosbag，用多个随机场景比较路径、时间、召回、虚警、失败和恢复指标。
6. 默认仍使用确定性 `HeuristicPolicy`。可选 `RLTaskPolicy` 只能在同一 `PolicyObservation -> PolicyAction` 接口中选择已生成候选或状态机动作；非法动作、超时、模型异常或连续无效决策立即回退启发式策略。
7. S4 优化只有在多随机场景中证明缩短探索时间、减少重复/失败或提高端到端得分，且不降低召回和虚警表现时，才能成为确认基线。

阶段算法摘要：

| 阶段 | 核心算法 | 目标选择 | 恢复/结束 |
|------|----------|----------|-----------|
| S0 | 简单前沿聚类 | 最近且 `make_plan` 可达 | 有限重试，人工 finish |
| S1 | WFD + 单层评分 | 信息增益减路径/重复/失败 | 冷却、黑名单、重验证、自动收敛 |
| S2 | 结构拓扑 + 贪心可见域覆盖 | 拓扑债务、房间视点、复核候选统一评分 | 债务结案与房间覆盖完成 |
| S3 | 分层拓扑图 + 通道效用 | 同层债务与楼梯/电梯在线选择 | 换层状态机与全楼层结束 |
| S4 | 风险感知统一效用 + 在线经验 | 计分台阶感知的多目标决策 | 诊断回放、策略回退与多场景确认 |

### 2.3 模块职责

探索规划模块负责：

- 适配定位与建图结果，维护分楼层探索地图。
- 区分自由、占用、未知、膨胀和不可通行区域。
- 从地图提取房间、走廊、房门、岔路、死端和垂直通道拓扑，并持久化未探索分支。
- 检测、聚类、过滤并评分走廊结构前沿及房间可见性观察候选。
- 选择导航目标，监控执行，并处理超时、阻塞、振荡和不可达。
- 管理房间扫描、门操作、楼梯/电梯选择与换层、定位修正后的重验证、恢复、结束和可选返航。
- 在不接触真值的前提下响应感知复核请求，为低置信、类别易混淆、位置不稳定或可能重复的目标安排异视角确认。
- 发布任务状态、当前楼层、地图/房间观察进度、候选目标、黑名单和停止原因。

探索规划模块不负责：

- 点云 SLAM、视觉 SLAM 或状态估计的具体实现。
- 危险源检测、分类、跨帧去重和最终结果文件生成。
- 四足步态、关节控制或底层速度闭环。
- 读取裁判真值或预先获得完整地图。

相邻模块未完成时应提供明确适配器和 mock，不得把定位、感知和导航实现耦合进探索节点。

### 2.4 统一任务决策框架

整个任务统一建模为“在定位、安全和正式输入约束下，用最小有效代价完成拓扑发现、房间视野覆盖和检测确认”。地图覆盖只是发现空间的中间指标，不是最终优化目标。

规划层次固定为：

```text
传感器、定位与建图
  -> 分楼层栅格、结构障碍和定位健康
  -> 房间/走廊/房门/岔路/垂直通道拓扑
  -> 走廊拓扑债务、房间可见域债务、检测复核债务
  -> 同楼层或跨楼层候选动作
  -> 评分、安全校验、导航执行和结果确认
```

三类持久任务债务：

- `TOPOLOGY_DEBT`：尚未服务的房门、岔路、走廊延伸、死端确认和垂直通道入口。
- `VISIBILITY_DEBT`：房间内尚未进入可靠视场的目标支持区域、遮挡物后方和失败观察方向。
- `VERIFICATION_DEBT`：低置信、类别不稳定、位置不稳定或疑似重复的危险源轨迹。

每个规划周期按以下顺序执行：

1. 校验定位、地图、楼层、结构障碍、感知和导航数据的新鲜度及版本；不稳定时先等待或恢复。
2. 更新当前楼层拓扑，新增、合并或失效拓扑债务，不因局部前沿消失而遗忘未探索分支。
3. 若在房间内，更新可见域和复核债务；若在走廊中，只做结构确认和入口登记，不启动细致覆盖。
4. 生成走廊前沿、房间视点、检测复核、门操作、楼梯、电梯、恢复和结束候选。
5. 先执行硬安全与合法性过滤，再按预期召回/降虚警收益减路径、时间、风险、重复和失败代价评分。
6. 使用迟滞保持当前仍有效的动作，只有新动作收益显著更高、当前动作失效或进入计分台阶决策点时才切换。
7. 执行后更新真实路径、等待、扫描、定位变化、检测确认和失败统计，作为后续在线代价。

房间和走廊共享候选生成、安全过滤、可见域估计和债务管理框架。区域标签不是目的，也不要求在边界证据不足时强行二分类；`UNKNOWN_REGION` 按当前可见域与拓扑收益保守探索。走廊标签使规划器优先确认开口和分支，房间标签使规划器优先覆盖危险源可能区域及遮挡后方。

每个执行动作还可产生高层运动模式或速度上限提示：`FAST_TRANSIT`、`NORMAL_EXPLORATION`、`CAUTIOUS_OBSERVATION`、`STAIR_TRAVERSAL`、`STOP_AND_SCAN`。提示只能收紧或建议 navigation 的速度，不得绕过 navigation/control 的局部安全限制；定位、建图或感知状态退化时必须自动降级到更保守模式。

统一动作价值使用以下概念，不要求所有候选共享完全相同的数值尺度：

```text
action_utility =
    expected_visibility_or_topology_gain
  + expected_detection_verification_gain
  + unresolved_debt_priority
  + destination_floor_gain
  - path_and_rotation_cost
  - operation_and_wait_cost
  - localization_and_safety_risk
  - revisit_and_failure_cost
  - score_step_overrun_cost
```

其中 `score_step_overrun_cost` 只反映超过 `600 s` 后每满 `60 s` 的离散时间扣分，不是硬截止。高价值未扫描房间、唯一分支和必要检测复核可合理跨越时间台阶；低新增可见域、重复走廊、无效等待和无边界恢复必须及时终止。

决策优先级：

1. 安全、定位有效和正式输入合规是硬约束。
2. 避免遗漏可达房间和楼层，降低召回率跌入 `<=60%` 零分区的风险。
3. 通过异视角确认、类别判别、定位修正和严格去重，将最终虚警率控制在 `<=10%`。
4. 在前述目标不受损的条件下尽量在 `600 s` 内完成；超过后按下一 `60 s` 台阶评估动作边际收益。
5. 地图覆盖率、原始检测数和已发现危险源数都不能单独触发结束。

正常结束必须同时满足：可达拓扑债务已清空或有明确不可达原因；房间可见域债务达到阈值且剩余死角已分类；检测复核债务已确认、合并或拒绝；定位和地图版本稳定；结果已按最新坐标修正去重并落盘。可选返航在结果冻结后执行，不参与普通探索决策。

## 3. 系统架构与策略接口

### 3.1 推荐结构

探索逻辑优先实现为独立 ROS 包 `exploration_planner`。算法核心应尽量与 ROS 解耦，ROS 节点只负责消息转换、参数读取和状态发布。

建议组件：

- `MapAdapter`：统一适配二维地图、可通行性、楼层和可选三维表面数据。
- `ExplorationMap`：维护自由、障碍、未知、访问热度、时间戳和地图版本。
- `FrontierDetector`：检测并聚类自由区与未知区边界。
- `StructuralTopology`：提取房间、走廊、门、岔路、死端和垂直通道节点，维护已服务状态与拓扑债务。
- `RoomCoveragePlanner`：按感知有效视场和遮挡轮廓生成观察位姿，以贪心可见域覆盖和短路径排序完成房间扫描。
- `CandidateEvaluator`：计算信息增益、路径、转向、风险、楼层和重复访问代价。
- `GoalManager`：管理去重、冷却、黑名单、超时和成功/失败统计。
- `MissionPlanner`：管理走廊探索、房间扫描、恢复、门、换层、结束和可选返航。
- `PolicyAdapter`：向规则策略或 RL 提供统一状态与动作接口。
- `SafetyValidator`：校验地图版本、可达性、状态合法性、局部超时和安全约束。
- `NavigationAdapter`：发送导航目标并统一反馈结果。
- `ExplorationMonitor`：发布进度、状态、目标、候选和停止原因。

不要把所有逻辑写进单个回调。传感器和地图回调只更新状态；规划循环以较低、可配置频率运行。

### 3.2 算法无关策略接口

系统必须分为“环境适配—候选生成—策略决策—安全执行”：

```text
队友 ROS 接口
  -> 状态适配器
  -> 候选目标生成
  -> PolicyObservation
  -> HeuristicPolicy 或 RLTaskPolicy
  -> PolicyAction
  -> SafetyValidator
  -> MissionPlanner 与 NavigationAdapter
```

规则策略与 RL 使用同一接口：

```text
PolicyAction selectAction(const PolicyObservation& observation)
```

`PolicyObservation` 至少包含：

- 当前时间、位姿、位姿不确定度和当前楼层。
- 定位健康、累计漂移指标、最近位姿跳变/重定位事件及坐标修正版本。
- 地图稳定性、各楼层版本、增长率和当前楼层摘要。
- `map_coverage`、走廊拓扑覆盖、未服务房门/岔路债务、房间可见域覆盖和未覆盖区域摘要。
- 已发现垂直通道的入口、连接楼层、结构置信度和可通行状态。
- 任务已运行时间、任务状态和可选返航代价。
- 距离 `600 s` 及后续 `60 s` 计分台阶的时间、当前扫描动作预期新增可见域和疑似检测复核价值；该时间信息只用于收益权衡，不构成硬截止。
- 导航健康、执行进度和最近动作结果。
- 已过滤、可评估的候选目标，以及可用门、电梯和换层选项。

每个候选至少包含：

- `candidate_id`、目标位姿、楼层和生成时地图版本。
- 前沿大小、地图信息增益、拓扑债务优先级或房间新增可见域。
- 所属区域类型、关联房门/岔路/房间、是否能观察遮挡物后方，以及与已有视点和方向的冗余度。
- 实际规划路径长度、障碍净空、通行风险、重复访问惩罚、失败次数、冷却状态和房间可能性。

`PolicyAction` 只能选择：

- `NAVIGATE_TO_CANDIDATE`
- `ROTATE_AND_OBSERVE`
- `OPERATE_DOOR`
- `CHANGE_FLOOR`
- `RUN_RECOVERY`
- `RETURN_HOME`
- `WAIT`
- `FINISH`

动作至少携带 `action_type`、候选 ID 或目标楼层、策略置信度、决策原因和地图版本。策略不得直接调用 ROS 服务、发送导航 Action 或发布速度。

默认使用 `HeuristicPolicy`：

```yaml
policy_type: heuristic  # heuristic | rl
```

后续 `RLTaskPolicy` 仅替换 `selectAction`，继续使用相同候选、地图适配、导航和安全状态机。RL 不得直接生成任意目标、绕过可达性与安全校验，也不得以二维地图覆盖率作为房间完成的唯一依据。

RL 训练数据由探索模块基于正式接口记录为结构化日志或 rosbag，包括地图与房间观察增量、路径长度、耗时、导航失败、换层成本、危险源检测事件和可选返航结果，不要求队友增加训练接口。模型加载失败、推理超时、异常退出、非法动作或连续无效决策时，必须自动回退到 `HeuristicPolicy`。正式运行不得依赖环境 reset、真值奖励、危险源真值或布局真值。

## 4. 队友接口基线

优先使用 ROS 标准消息和 Action，并通过参数配置话题名。除确有必要的团队状态、危险源检测和垂直通道结构外，不创建算法专用接口。

### 4.1 定位与建图

按阶段提供；TF、定位、占据地图和状态为硬依赖，派生层按下述降级语义接入：

- `/tf`：连续 `map -> odom -> base` 变换；`base` 与机器人配置一致。
- `/localization/pose`：`geometry_msgs/PoseWithCovarianceStamped`，包含位姿、时间戳和不确定度。
- `/localization/status`：至少包含 `tracking_state`、协方差摘要、漂移告警、最近位姿跳变、重定位事件、坐标修正版本和更新时间。
- `/map`：当前楼层 `nav_msgs/OccupancyGrid`，`frame_id=map`，使用 `-1=未知、0=自由、100=占用`，供前沿检测和二维导航。
- `/mapping/current_floor`：当前楼层，索引从 `0` 开始。
- `/mapping/status`：至少包含 `ready`、`stable`、`lost`、`current_floor`、各楼层 `map_version` 和最近更新时间。
- `/mapping/obstacle_structure`：当前楼层结构化障碍派生层，至少区分 `STRUCTURAL_BOUNDARY`、`INTERIOR_OCCLUDER`、`TRANSIENT` 和 `UNKNOWN`，并提供二维轮廓、高度是否已知、分类置信度、几何完整度、持久性、观测状态和 `source_map_version`。它解释房间边界与视线遮挡，不复制 `/map` 的占据事实，也不要求桌、椅、柜等类别。
- `/mapping/traversability`：可选增强接口，表达占据图无法覆盖的运动风险，至少区分未知、可通行、不可通行和谨慎通行，并携带 `source_map_version`。普通自由/占用以前沿地图为准，普通导航可达性以 `/move_base/make_plan` 为最终查询；无法稳定提供时允许明确降级，不得发布虚假的全图可通行占位。
- `/mapping/vertical_connection_observations`：垂直通道增量观测假设。每项至少包含稳定观测 ID、单调修订号、可选轨迹提示、当前观测楼层、类型 `STAIR|ELEVATOR|UNKNOWN`、局部入口与已观测轮廓、可选已见路径、远端是否已知、几何完整度、分类置信度、通行风险、观测状态、`source_map_version` 和 `source_correction_version`。首次发现不要求知道连接楼层、远端入口或完整结构；首版数组按当前快照发布，撤销项以 `INVALIDATED` 保留约定周期。

上述 `/mapping/*` 命名不等于全部由 SLAM 负责人实现。定位建图负责位姿、TF、占据事实和版本；普通可达性由导航 `make_plan` 负责；结构障碍和垂直通道观测由逻辑上的“环境结构适配器”提供，可落在建图后处理、独立节点或探索 ROS 壳层；探索核心负责假设融合、拓扑债务和确认后的跨层边。框架阶段只需冻结派生消息与 mock 插槽，具体生产者在联调时确定。通行风险层是增强接口，缺省时由 `make_plan` 和垂直通道自身风险字段降级，不得与占据地图重复维护普通可达性。

垂直通道要求：

- 楼梯允许从疑似入口开始，以 `TENTATIVE/PARTIAL` 逐步补充已观测中心线、平台、宽度、坡度/台阶、净空和远端；未知字段保持未知，不得虚构完整连接。
- 电梯允许逐步补充厅门入口、门槛、可停靠轿厢区域、当前可进入状态和对应楼层；错误假设必须以 `INVALIDATED` 显式撤销。
- `/map` 只标实际观测到的自由、占用和未知几何，不使用非标准栅格值标记楼梯/电梯，也不绘制未观测远端；语义位置来自垂直通道观测，确认后的跨层边只保存在探索拓扑中。
- 任务模块负责把公开门/电梯服务 ID 与已发现几何实体关联；建图模块不得读取布局真值完成关联。

质量要求：

- 地图建议至少 `1 Hz`，TF 建议至少 `10 Hz`。
- 二维地图、结构障碍、可通行性和垂直通道观测必须通过 TF 对齐并用 `source_map_version` 建立一致性；不强求不同更新频率的话题使用完全相同时间戳。
- 占据地图、结构障碍层和可通行性必须能相互关联；墙体用于房间/走廊边界，内部遮挡物用于房间视线规划，低置信或无法分类的障碍按保守遮挡处理。
- 换层期间报告 `stable=false`；各楼层地图独立保存，不得投影混层。
- 回环、重定位或地图坐标调整时递增地图/坐标修正版本并发布修正事件，不得静默改变历史目标坐标。
- 不得使用裁判真值位姿或真值布局。

`/mapping/occupied_voxels`、OctoMap、TSDF、ESDF 和 `/mapping/surface_cloud` 均不是探索核心的必需接口。它们可作为建图或结构提取内部实现；`surface_cloud` 只在 S4 调试、回放或双方明确启用的 ROS 壳层降级适配器中作为可选输入，不能阻塞普通前沿探索或房间扫描。房间扫描默认消费轻量功能性障碍轮廓与高度范围，垂直规划默认消费增量通道观测。

### 4.2 导航控制

默认接口：

- `/move_base`：`move_base_msgs/MoveBaseAction`
- `/move_base/make_plan`：`nav_msgs/GetPlan`，用于可达性和实际路径长度估计
- `/move_base/clear_costmaps`：导航恢复
- `/navigation/path`：建议发布 `nav_msgs/Path`
- `/navigation/health`：至少包含 `ready`、`stuck`、`fallen` 和控制器是否生效

导航反馈必须区分成功、不可达、取消、超时和控制失败；标准 `MoveBaseAction` 终态使用 actionlib `GoalStatus`，细分失败原因通过 status text 或 `/navigation/health.failure_code` 表达。取消目标后必须停止旧目标速度。沿用团队框架边界：导航发布 `/danger_search/nav_cmd_vel`，control 负责安全仲裁并作为 `/cmd_vel` 的唯一最终发布者；探索模块只发送当前楼层目标或经验证的楼梯通行任务，不直接发布速度。

S4 速度增强沿用同一职责边界：探索可随目标提供任务模式或最大线/角速度建议；navigation 根据局部障碍净空、路径曲率、控制稳定性和该建议计算实际期望速度；control 继续执行硬安全上限、加速度限制和超时停车。若当前 `MoveBaseGoal` 无扩展字段，优先使用参数化速度配置、独立低频模式话题或导航侧目标上下文适配，不为此绕过现有 `/move_base` Action，也不允许探索直接发布 `/danger_search/nav_cmd_vel` 或 `/cmd_vel`。

现有 `unitree_move_base` 使用 `odom` 滚动全局代价地图，并依赖 `/faceLaserScan`、`/leftLaserScan`、`/rightLaserScan`。正式接入前应改为使用 SLAM 地图和由允许传感器合法生成的障碍输入，同时保持 `robot_base_frame: base`。

### 4.3 危险源感知

必须提供：

- `/danger_detector/detections`：检测 ID、类别、位置、坐标系、时间戳、置信度和确认状态。
- `/danger_detector/status`：检测器可用性和最近有效输入时间。
- `/danger_detector/observation_done`：当前观察位姿是否完成稳定检测。
- 感知能力参数或状态：有效水平/垂直视场、可靠检测距离、稳定等待时间和允许扫描角速度，供房间可见域规划；参数可由配置提供，不要求新增高频话题。
- 检测轨迹与复核语义：至少提供稳定 `track_id`、位置协方差、楼层、生成时定位修正版本、`verification_required` 和可能重复的关联信息。感知可请求从不同方向再次观察，探索模块只负责安排安全可达视点。

感知或结果模块负责红球、红方块和绿球分类、跨帧/跨视角去重、定位修正后的坐标更新与结果写入。未检测到危险源不代表房间扫描完成；观察完成事件必须与检测结果分开。最终文件只写入已确认且去重后的危险源轨迹，不能把同一目标的多个观测点分别输出。

### 4.4 任务与结果

沿用团队框架现有接口：

- `/danger_search/start`：`std_srvs/Trigger`，由 mission 提供，作为用户启动整个任务的唯一正式入口；mission 再调用模块级 `/danger_search/start_exploration`。
- `/danger_search/finish`：`std_srvs/Trigger`，由 mission 提供；报告正常完成或异常结束，停止探索、冻结计分时间并触发结果最终落盘。
- `/danger_search/return_home`：`std_srvs/Trigger`，由 mission 提供的可选返航入口，不是完成前置条件。
- `/danger_search/start_exploration`、`/danger_search/stop_exploration`：`std_srvs/Trigger`，由 exploration 提供，仅供 mission 编排和模块独立测试。
- `/mission/status`：`danger_search_common/MissionStatus`，由 mission 发布任务开始时间、已运行时间、当前阶段和结束原因；不包含硬总时限或强制剩余时间。
- `/mission/active`：`std_msgs/Bool`，由 mission 以 latch 方式发布任务是否激活。

不存在基于剩余时间的 `/mission/return_required`。算法仍须限制单次等待和恢复，并在在线收敛后调用现有 `/danger_search/finish`。mission 持续维护检测结果并最终写入 `results/detected_danger.json`。

探索模块直接调用 `/set_door_state` 和 `/call_elevator` 管理高层门、电梯流程；导航模块执行同楼层目标、门前/电梯厅/轿厢/出口目标和经验证的楼梯路径。

### 4.5 通用输入输出契约

实现前应与各负责人确认接口；未确定时使用标准消息、参数化话题名和 mock，不硬编码团队私有话题。

探索输入至少包括：位姿、定位健康及坐标修正版本、当前楼层二维占据地图、引用源地图版本的结构障碍层、可选通行风险层、增量垂直通道观测、导航反馈与剩余路径、感知有效视场与观察完成事件、门和电梯服务状态。原始带高度点云不是默认规划输入。危险源事件可辅助记录观察过程，但不得单独决定探索完成。

探索输出至少包括：带坐标系和时间戳的导航目标、取消/重规划请求、任务状态与楼层、地图/走廊拓扑/房间可见域进度、剩余前沿与拓扑债务、停止原因，以及 RViz 前沿/候选/目标/黑名单标记。

所有坐标必须显式标注坐标系。跨楼层目标至少携带楼层编号或可靠 `z`；最终危险源使用 `world` 坐标，但探索不得依赖 Gazebo 真值位姿。S0 即须冻结 `map -> world` 契约：若二者不重合，定位侧提供连接 TF（推荐 `world` 为父、`map` 为子）或结果侧用允许的 `team_scene_info.json` 起点建立等价静态变换；不得只改 `frame_id`，转换不可用时不得静默把 map 坐标写入结果。

## 5. 探索算法基线

### 5.1 地图与进度

- 明确定义 `free`、`occupied`、`unknown`、`inflated` 和不可通行状态。
- 按 A1 尺寸、定位误差和控制误差膨胀障碍。
- 过滤孤立噪声、小孔洞和瞬时伪影，避免虚假前沿。
- 用时间戳或版本号识别真实地图更新，避免原地重复规划。
- 维护访问热度和轨迹覆盖，对走廊往返与重复停留惩罚。
- 分楼层保存地图，避免不同高度投影混层。
- 楼梯、门口、电梯厅和轿厢使用更大、可配置安全裕量。

“已探索”不等于机器人经过，也不等于二维栅格已知。未知完整地图无法使用真值面积作为覆盖率分母，因此分区维护：

- `map_coverage`：地图已知区域、有效前沿和地图增长情况。
- `corridor_topology_progress`：已确认走廊段、房门、岔路、死端和垂直通道，以及未服务拓扑债务。
- `room_visibility_progress`：每个房间的可见域覆盖、遮挡后方剩余区域、计划/完成观察位姿、观察方向和感知完成状态。

机器人无须踩遍每个自由栅格。走廊只需把结构、房门和岔路看清并保证所有拓扑债务得到服务；房间则需从有效距离和方向覆盖危险源可能出现且未被墙体或内部障碍遮挡后的区域。

这种区分是轻量的任务语义，不是两套互斥探索算法。走廊和房间都需要让相关未知区域进入传感器有效视场，但因危险源只生成在房间，二者的相关区域和完成条件不同：走廊关注拓扑开口是否被发现和确认，房间关注危险源支持区域是否获得无遮挡视觉覆盖。开放式房间、宽走廊或边界未闭合时允许保持 `UNKNOWN_REGION`，使用统一信息增益继续探索，直到证据足以分类。

动态速度初始规则：

- 已确认安全、已探索、开阔且定位稳定的通路可使用 `FAST_TRANSIT`。
- 新进入的未知走廊使用 `NORMAL_EXPLORATION`，给地图更新和分支登记留下观测时间。
- 房门、岔路、死端、疑似垂直入口和房间扫描使用 `CAUTIOUS_OBSERVATION`，必要时 `STOP_AND_SCAN`。
- 楼梯、门槛、电梯厅、轿厢、狭窄或低净空区域使用 `STAIR_TRAVERSAL` 或等价低速模式。
- 定位协方差增长、漂移告警、地图快速变化、图像/深度输入不新鲜或检测稳定条件不足时降速或暂停。
- 提速必须同时满足几何安全、定位稳定、建图有效观测、感知稳定检测和导航控制约束；任何一项要求更低速度时取其更保守上限。

这些模式是待多场景实验标定的策略语义，不是固定速度数值。必须记录模式、实际线/角速度、定位健康、地图增长、漏分支回溯、检测输入新鲜度和导航失败，用于比较提速是否真正节省总时间而没有降低召回或地图质量。

### 5.2 走廊拓扑探索与岔路规划

使用 WFD 或等价 BFS 发现未知空间，但在走廊中将前沿进一步归并为走廊延伸、房门/开口、岔路分支、死端和垂直通道入口。探索模块从结构墙体、自由空间宽度和连通关系构建每层拓扑图；分类不确定时保留 `UNKNOWN_PORTAL`，不得直接删除。

每发现一个尚未进入或尚未确认终止的房门、岔路或垂直通道，就创建持久化拓扑债务，记录节点 ID、父走廊、发现位姿、朝向、楼层、地图版本、可达状态、尝试次数和最后观测时间。地图当前不再显示前沿、发生回环或机器人离开局部区域时，债务仍保留，直到完成、确认不可达或地图修正后失效。

走廊执行规则：

1. 沿走廊中心或高净空带前进，以一次通行为主，不做沿墙逐格覆盖。
2. 经过房门或岔路时进行短时定向观测，确认入口几何并登记债务；无需像房间一样全向慢扫。
3. 当前走廊到达死端或低收益区域后，优先回溯最近且低代价的未服务债务；存在环路时在拓扑图上运行 Dijkstra/A* 或最佳优先搜索，不使用纯栈式 DFS 重走长路径。
4. 临近未服务房门和岔路优先于远处同收益前沿，避免先跨越大量已知区域后再返回；但高价值主走廊可暂时延后小分支，债务年龄会逐步提高其优先级。
5. 结束当前楼层前，必须清空可达拓扑债务，或为每项留下有限重试后的明确不可达原因。

走廊候选评分在原有地图增益和路径代价之外加入：

```text
score =
    map_gain_weight * map_information_gain
  + topology_gain_weight * expected_new_portals
  + branch_debt_weight * debt_priority
  + room_entry_weight * expected_room_value
  - path_cost_weight * path_cost
  - risk_weight * traversal_risk
  - revisit_weight * revisit_penalty
  - failure_weight * failure_penalty
```

所有特征先归一化。`debt_priority` 综合债务年龄、附近未访问开口数、是否为唯一未服务分支和回溯成本；不能只以欧氏距离或最近前沿决策。

### 5.3 房间可见性覆盖扫描

工作假设是：危险源只要进入检测器有效视场、距离和稳定观测条件，就能迅速被发现。因此房间规划目标不是覆盖全部地面路径，而是用尽量短的移动和旋转使所有可能放置危险源的区域至少一次进入无遮挡有效视场。

建图提供的障碍分类只需支持功能性视线判断：

- `STRUCTURAL_BOUNDARY`：墙体或固定建筑边界，用于房间轮廓和出入口分割。
- `INTERIOR_OCCLUDER`：位于房间内部、可能遮挡低矮危险源的固定或长期障碍。
- `TRANSIENT`：短时动态障碍，不据此永久切分房间或生成长期扫描债务。
- `UNKNOWN`：无法可靠分类，房间扫描时按遮挡物保守处理，后续观测可更新。

首版使用二维/2.5D 可见性近似，不要求完整体素或家具类别：根据房间边界、障碍轮廓、高度范围、相机有效视场和可靠检测距离，从房门内侧、自由空间骨架、房间角区及内部遮挡物不同侧生成安全候选；对候选做射线投射，估算新增可见区域。高度信息用于判断障碍是否会遮挡从相机到低矮球体的视线，无法判断时按遮挡处理。

房间执行流程：

1. 穿过房门后建立房间局部边界并做一次快速入口扫描，同时避免把走廊区域并入房间。
2. 生成能看到最大未覆盖区域的候选观察位姿和朝向；候选必须可达、与障碍保持安全距离并满足定位不确定度裕量。
3. 反复选择“新增可见域收益减路径、旋转、风险和冗余代价”最大的视点，形成贪心集合覆盖；再用最近邻加局部改进或小规模 TSP 对已选视点排序。
4. 到点后按感知有效 FOV 留重叠地分段旋转，而不是固定 `60°`；每段等待关联任务 ID 的 `observation_done`，快速检测假设只减少停留时间，不取消稳定完成确认。
5. 若新障碍或新房间边界出现，增量更新未覆盖区域和后续视点；已覆盖区域不重复扫描。
6. 当所有可达候选的新增可见域低于阈值、目标支持区域达到覆盖阈值且观察事件完成时结束；不可见死角必须记录为 `OCCLUDED_UNREACHABLE`，不能静默视为已覆盖。

房间扫描评分建议：

```text
room_score =
    visible_gain_weight * newly_visible_target_area
  + occlusion_reveal_weight * newly_revealed_occluder_backside
  - path_cost_weight * path_cost
  - rotation_cost_weight * required_rotation
  - risk_weight * traversal_risk
  - redundancy_weight * overlap_with_observed_area
  + verification_weight * pending_detection_verification_value
```

普通开阔房间通常应自然收敛到 `1～2` 个视点；复杂遮挡房间允许按实际可见域增加视点，不再硬编码最多 `3` 个。必须设置最小新增可见域、最大单房间扫描时长和不可达终止条件，避免追求理论无死角而无限运行。若结构障碍接口暂不可用，降级为房门内侧、中心和障碍不同侧的保守多视点规则，并明确标记覆盖置信度降低。

若感知产生低置信红色目标、球/方块类别不稳定、位置协方差过大或疑似与已有轨迹重复，房间规划应把“从显著不同方向复核”作为高价值候选。复核成功后合并到同一 `track_id`；复核失败或定位修正后位置不一致时不得直接落盘。由于一对一匹配会把重复点计为虚警，复核和去重的收益通常高于对已充分覆盖区域继续做低增益扫描。

### 5.4 多楼层、岔路与垂直通道调度

每层独立维护地图摘要、房间/走廊拓扑、房间可见域、拓扑债务、通道经验代价和失败记录。默认优先完成当前位置附近的房间与分支，但不要求机械地“整层全部完成后才能换层”；当当前层剩余目标低收益或高代价，而其他楼层存在高置信高收益债务时，可进行全局调度。

对每个“目标楼层—垂直通道”组合估算：

```text
cross_floor_utility =
    expected_floor_gain
  + unresolved_debt_value
  - path_to_entrance_cost
  - expected_wait_and_operation_time
  - traversal_time
  - localization_risk
  - safety_risk
  - failure_probability_cost
  - future_reposition_cost
```

楼梯通常适合相邻楼层、无需等待且结构已确认的情况，但需承担足滑、跌倒、窄平台和连续里程计漂移风险；电梯通常适合跨多层或楼梯风险高的情况，但需承担呼梯/开关门时间、服务失败、轿厢运动期间定位失稳和出口关联错误。不得固定“永远走楼梯”或“永远坐电梯”。

通道初始代价来自配置和结构置信度，执行后用真实等待时间、通行时间、失败次数、定位协方差增长和恢复耗时更新指数滑动平均。安全状态硬约束优先于效用：机器人摔倒、楼梯不可通行、电梯状态未知或定位无法在出口重稳定时，不得仅因理论路径短而选择该通道。

当前层仍有附近高价值房间、唯一未服务分支或尚未确认的出口时不应频繁换层。跨层后保留原楼层债务；全局任务结束前统一检查所有楼层的可达债务，而不是只检查当前地图前沿。

### 5.5 状态机与恢复

任务必须使用显式状态机：

- `WAIT_FOR_INPUTS`：等待稳定定位、地图和导航。
- `EXPLORE_CORRIDOR`：发现走廊结构、房门、岔路、死端和垂直通道，登记并服务拓扑债务。
- `SCAN_ROOM`：在已进入房间内执行可见性覆盖视点和分段转向。
- `RECOVERY`：处理不可达、阻塞、振荡和地图异常。
- `OPERATE_DOOR`：操作门并重新检查通路。
- `ENTER_ELEVATOR`：到厅、呼梯、开门并进入轿厢。
- `CHANGE_FLOOR`：通过楼梯，或关门并呼叫电梯至目标楼层。
- `EXIT_ELEVATOR`：开目标楼层门并离开轿厢。
- `RETURN_HOME`：可选，返回公开起点附近。
- `FINISHED`：停止探索目标并发布结束原因。
- `ABORTED`：不可恢复错误时安全停止并保留诊断。

状态转换必须由可观测条件触发，不只依赖固定延时。门动作可能持续约 `25 s`，需结合服务返回、超时和通路复检。换层前保存楼层摘要；离开楼梯或电梯后等待定位与地图稳定再恢复规划。

每个目标记录唯一 ID、发送时间、地图版本和尝试次数。恢复规则：

- 无全局路径：降低评分或加入短期黑名单。
- 导航失败：记录位置和原因，尝试附近替代点。
- 长时间无进展：取消并局部恢复或重规划。
- 已接近目标但无法精确到达：满足可配置观察距离时可判定完成。
- 地图更新使目标落入障碍或失效：取消并重新评分。
- 定位协方差超限、`map->odom` 跳变或发生重定位：立即暂停发新目标；必要时取消活动目标，等待稳定后按新坐标修正版本重投影或重新生成目标，并复核拓扑节点、房间覆盖和未确认检测位置。
- 多次失败：扩大黑名单和冷却；地图显著变化后允许重试。
- 无候选但未完成：旋转观测、返回最近分叉点、检查门或换层，不得原地无限等待。

所有恢复动作必须限制次数和总时长。

### 5.6 结束与可选返航

禁止使用危险源真值数量作为结束条件。正常结束综合：

- 已访问楼层连续多个周期无有效可达前沿。
- 所有已发现且可达的房门、岔路和垂直通道拓扑债务均已服务。
- 地图新增已知区域持续低于阈值。
- 房间可达目标支持区域达到可见域覆盖阈值，所有观察任务已完成，剩余死角均有明确不可达原因。
- 所有公开可服务楼层已访问，或剩余楼层在有限重试内不可达。
- 所有待复核检测均已确认、合并或明确拒绝；最终候选已使用最新定位修正版本转换到 `world` 坐标。

没有总任务硬时限，不得因虚构倒计时提前结束；但评分在 `600 s` 内时间满分，之后每满 `60 s` 扣 `1` 分。规划器应估算跨越下一计分台阶前能否完成高价值房间、拓扑债务或检测复核：高召回/降虚警动作可合理跨越台阶，低新增可见域和重复恢复不得无目的跨越。在线指标收敛后立即落盘，不能为形式上的“全覆盖”无限运行。

返航只在策略配置、安全测试或外部要求时执行。结果应在探索与检测确认完成后立即最终落盘并固定 `exploration_time`；可选返航不得延迟计分文件或把返航时间计入探索完成时间，除非正式规则后续明确要求。若启用返航，成功定义为进入 `team_scene_info.json` 公开起点的可配置半径；返航失败也必须在有限重试后结束并报告原因。

### 6.2 测试要求

探索核心必须可脱离 Gazebo 单元测试，至少覆盖：

- 空、全未知和全已知地图不崩溃。
- 简单房间产生正确方向前沿；噪声、小孔洞不产生虚假目标。
- 走廊房门、T/Y/十字岔路、环路和死端能形成正确拓扑，未探索分支在离开局部地图后仍保留。
- 开阔房间以少量视点完成；有内部遮挡物时能生成其不同侧视点，并且不可达死角不会误记为已覆盖。
- 不可达前沿被过滤或降级；评分能权衡信息增益、路径和重复访问。
- 目标失败进入冷却，地图显著变化后可重新启用。
- 连续无前沿触发恢复、换层或结束；可选返航仅在启用时触发。
- 门、电梯服务超时、失败和重试正确。
- 不同楼层地图与目标不串层。
- 定位渐进漂移告警、回环跳变和重定位后，活动目标、拓扑节点和房间覆盖会暂停并重验证。
- 同时存在楼梯和电梯时，通道选择能随等待时间、风险、失败和目标楼层收益变化，而不是固定选择一种。
- 同一危险源的多帧、多视角和重定位前后观测能合并为单一输出；红方块、绿色球和低置信红球不会未经复核进入最终结果。
- 在 `600 s` 前后及连续 `60 s` 台阶附近，策略能优先保留高召回/降虚警动作并终止低收益重复扫描。

仿真集成至少覆盖：

- 单房间走廊、多房间窄门。
- 至少两层楼梯场景，验证入口、中心线/可行走带、平台和上下出口结构。
- 至少两层电梯场景。
- 不可达前沿、动态门关闭、导航失败、定位抖动和地图短时停更。
- 完成后立即落盘并停止普通目标；启用返航时验证返航状态。
- 危险球被桌柜或沙发遮挡，单一门口/中心视角不足，需要不同方向观察点。
- 复杂走廊含多个岔路和环路时不遗漏房门，且回溯路径明显少于纯栈式 DFS 或最近前沿基线。
- 无全局占据体素地图时仍能扫描；结构障碍层缺失时进入保守多视点降级，`/mapping/surface_cloud` 中断不应阻塞普通房间扫描，垂直通道识别则进入明确等待或降级状态。
- 注入足滑漂移、长走廊弱约束、回环修正及电梯内定位失稳，验证暂停、重定位和目标重验证流程。

每次仿真记录：

- 总探索时间、结果落盘时间和启用时的返航时间。
- 路径长度、地图增长曲线、无目标等待时间和恢复次数。
- 目标数量、成功率、失败率和重复比例。
- 每层耗时和换层次数。
- 危险源发现数量，仅用于端到端评估。
- 评估脚本的 `correct`、`missed`、`false_alarms`、召回率、虚警率、三项得分和 `technical_objective_total`，仅由隔离 evaluator 计算。
- 房间计划/完成观察点、补扫成功率和补扫耗时。
- 走廊拓扑节点、未服务债务、遗漏房门/岔路、拓扑回溯距离和重复走廊比例。
- 房间可见域覆盖、每视点新增可见域、不可达死角、视点数量和旋转耗时。
- 各垂直通道等待/通行/恢复时间、失败率、定位不确定度增长和被选择次数。
- 定位暂停次数、位姿跳变幅度、重定位耗时及修正后失效目标数。

至少使用多个随机种子回归；正式规划节点不得读取种子对应的真值文件。

### 6.3 完成标准

- 地图和位姿有效时持续产生合理、可达、非重复目标。
- 导航成功能推进探索，失败能自动恢复且不死循环。
- 能识别并使用至少一种垂直通道，完成楼梯或电梯换层并恢复探索。
- 无有效目标时给出明确原因并结束，不因无总时限而无限等待。
- 启用返航时，返航阶段不再派发普通探索目标。
- 正式输入符合赛题边界，不使用真值捷径。
- 核心策略有单元测试，ROS 接口有最小集成测试，关键状态可在 RViz 或日志观察。

### 6.4 分阶段交付

1. `S0`：冻结最小 ROS 适配接口，用 DFS/简单前沿完成至少一次移动、任务结束、结果落盘和官方 evaluator 解析。
2. `S1`：完成前沿收敛、有限恢复、目标冷却、定位修正重验证和单楼层自动结束。
3. `S2`：完成结构分区、持久拓扑债务、房间射线可见域、贪心视点、观察完成与检测复核。
4. `S3`：完成垂直通道部分观测融合、楼梯/电梯换层、分层债务保存和换层后定位恢复。
5. `S4`：完成风险与效率代价、RViz/结构化诊断、多随机场景回归和可选策略插件。

后续优化必须用缩短探索时间、减少重复路径、降低失败目标比例或提升端到端召回率等指标证明收益。
涉及感知和任务结束的优化还必须报告虚警率、重复输出数、定位修正后坐标误差，以及按 `docs/evaluation.md` 计算的客观总分；不得只比较地图覆盖率或原始检测数量。

## 7. 开发约束

- 修改聚焦探索与任务规划，不顺手重构仿真环境或底层控制器。
- 不提交或手工修改 `build/`、`devel/`、`logs/`、缓存和仿真生成物。
- 不覆盖用户已有改动；仓库可能存在未提交的构建或运行产物。
- 新代码遵循现有 catkin/ROS1 结构，补齐 `package.xml`、`CMakeLists.txt`、launch、config 和必要文档。
- 优先确定性算法和固定随机种子测试；日志记录关键参数和停止原因。
- 高频回调避免阻塞服务、全图重复扫描和昂贵路径规划。
- 所有服务和导航请求必须有超时、取消和异常处理。
- 每次改动先运行最小相关测试，再运行包级构建或集成测试；不修复无关失败。
